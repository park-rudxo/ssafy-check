# SSAFY 출석 체크 알리미 (크롬 익스텐션)

SSAFY 교육생이 **입실(09:00 이전)·퇴실(18:00 이후)** 체크를 놓치지 않도록 도와주는 크롬 익스텐션입니다.

> 퇴실 버튼은 미리 눌러도 되지만, **18:00 이후에 누른 기록이 있어야** 정상 퇴실로 인정됩니다. 18시 이전 기록만 있으면 조퇴 처리될 수 있습니다.

> **배포는 크롬 웹스토어로만 합니다.** zip 을 풀어서 설치하거나 `업데이트.bat` 으로 갱신하는 방식은 **더 이상 쓰지 않습니다.** 저장소에 남아 있는 `업데이트.bat` / `update.ps1`, 그리고 Release 에 첨부되는 설치용 zip 은 웹스토어 이전에 쓰던 것으로, 지금은 쓰이지 않습니다.

## 기능

### 🟥 빨간 사각형 강조 (콘텐츠 스크립트)
`edu.ssafy.com` 접속 시 **입실/퇴실 버튼 위에 네모 박스를 겹쳐 그려서** 지금 눌러야 할 버튼을 알려줍니다. 박스는 버튼의 실제 화면 위치를 따라가며(스크롤해도 유지), 상황에 따라 색과 문구가 바뀝니다. 남은 시간은 **초 단위로 매초 실시간 갱신**됩니다.

| 상황 | 동작 |
|---|---|
| 평일 09:00 이전 + 입실 안 함 | 입실 버튼에 **빨간 박스** + "입실 체크! 09:00 마감 (N시간 N분 N초 남음)" 라벨 |
| 평일 09:00 이후 + 입실 안 함 | 입실 버튼에 **빨간 박스** + "입실 체크 안 됨! 지금 체크" 라벨 |
| **입실 버튼 클릭 후** | 입실 박스 사라짐 (시각과 무관, 오늘 하루 유지) |
| 평일 09:00~18:00 (입실 완료) | 퇴실 버튼에 **주황 점선 박스** + "퇴실은 18:00 이후에" 라벨 |
| 평일 18:00 이후 + 유효한 퇴실 기록 없음 | 퇴실 버튼에 **빨간 박스** + "지금 퇴실하세요!" 라벨 + 상단 경고 배너 |
| **18:00 이후에 퇴실 버튼 클릭 후** | 퇴실 박스 사라짐 |

> 빨간 박스는 깜빡이며 강하게, 주황 점선 박스는 "아직 누르지 말고 기다리라"는 안내용입니다. 박스는 클릭을 막지 않으므로 버튼은 그대로 누를 수 있습니다.

### 🛡️ 서버에 실제로 찍힌 시각으로 판단 (조퇴/지각 방지)
SSAFY 홈의 출석 위젯에는 **서버에 기록된 입실·퇴실 시각이 그대로 표시**됩니다. 이 값을 읽어서 판단하므로, 이 브라우저에서 눌렀는지 여부와 무관하게 실제 상태를 압니다.

```html
<div class="wrap-going">
  <div class="state inRoomEnd"><span class="t1">08:25</span> 정상 출석</div>
  <div class="state2 outRoomEnd"><a id="checkOut"><span class="t1">18:03</span>퇴실하기</a></div>
</div>
```

입실은 문구가 `입실하기` → `정상 출석`으로 바뀌지만, **퇴실은 누른 뒤에도 문구가 `퇴실하기` 그대로이고 `.t1`에 시각만 찍힙니다.** 그래서 퇴실 여부는 문구가 아니라 이 시각으로만 판별할 수 있습니다.

덕분에 이런 경우가 모두 정확히 처리됩니다.

| 상황 | 동작 |
|---|---|
| 폰·다른 PC로 퇴실 | 위젯에서 읽어 **헛경고 안 감** |
| 브라우저 데이터 삭제 | 클릭 기록과 무관하므로 **영향 없음** |
| **눌렀지만 서버에 안 들어감** | 위젯에 시각이 안 찍히므로 **경고를 계속 보냄** |
| 18시 이전(예: 13:50)에만 누름 | `🚨 13:50 기록뿐! 지금 다시 누르세요` 로 **문제를 콕 집어 알림** |

세 번째가 특히 중요합니다. 클릭 이벤트만 믿으면 네트워크 실패나 세션 만료로 실제 퇴실이 안 됐는데도 확장이 안심시켜버리는데, 이 경우 조퇴 처리를 그대로 맞게 됩니다.

- **클릭 직후 90초는 유예**를 둡니다. 서버 반영에 시간이 걸릴 수 있어서, 이 동안은 클릭 기록을 임시로 인정하고 그 뒤에는 위젯에 실제로 반영됐는지로만 판단합니다.
- 위젯을 읽을 수 없는 화면(커리큘럼·로그인 등)에서는 기존처럼 클릭 기록(`localStorage`)으로 판단합니다.
- 18시 이전에 퇴실을 누르면 "18시 이후에 한 번 더 눌러야 인정된다"는 안내 토스트를 띄웁니다.

### 🔔 크롬 알림 (백그라운드)
크롬 알림이 가는 경우는 다음 **3가지뿐**입니다. (Mattermost 알림은 아래 별도 항목 참고) SSAFY 페이지를 열어두지 않아도 평일에 알림이 오며, 리마인더 알림을 클릭하면 SSAFY 출석 페이지가 열립니다.

- **08:50** — 입실 10분 전: "09:00 전에 입실 체크하세요"
- **17:50** — 퇴실 10분 전: "18:00 10분 전이에요! 정리하고 퇴실 준비하세요"
- **새 GitHub Release 발행 시** — 아래 "업데이트 공지 전달" 참고

> 크롬이 실행 중이어야 알림이 옵니다. 주말·공휴일·등록한 휴무일에는 강조/알림이 동작하지 않습니다.

### 💬 Mattermost 알림 (background.js)
출석 상태를 **Mattermost로 메시지 전송**합니다. 크롬 알림은 자리를 비우거나 크롬을 닫으면 못 보지만, Mattermost는 **폰 앱으로 푸시가 오기 때문에** 퇴실을 놓치기 훨씬 어렵습니다.

보내는 내용은 팝업의 **💬 Mattermost 알림** 섹션에서 각각 켜고 끌 수 있습니다.

| 종류 | 언제 | 예시 |
|---|---|---|
| 입실 체크 완료 | 입실 버튼을 누른 직후 | `✅ 입실 체크 완료 (08:47)` |
| 퇴실 체크 완료 | **18:00 이후** 퇴실 버튼을 누른 직후 | `✅ 퇴실 체크 완료 (18:03)` |
| 미체크 경고 | 08:50 / 08:55 / 08:58 (입실 안 함)<br>18:00 / 18:05 / 18:15 / 18:30 (퇴실 안 함) | `🚨 아직 퇴실 체크를 안 했어요! 18:00에서 15분 지났어요.` |

- **미체크 경고는 체크할 때까지 반복**해서 옵니다. 체크가 확인되면 그 시점부터 더 이상 오지 않습니다.
- 18:00 **이전**에 누른 퇴실 클릭은 "완료"로 알리지 않고, 경고도 계속 보냅니다. (18시 이전 기록만으론 조퇴 처리될 수 있으므로)
- 입실 여부는 클릭 기록뿐 아니라 **페이지의 "정상 출석" 문구로도 확인**하므로, 폰이나 다른 브라우저로 입실했어도 헛경고가 가지 않습니다.
- 같은 알림은 하루 한 번만 갑니다. SSAFY 탭을 여러 개 열어둬도 중복 전송되지 않습니다.
- 메시지 카드에 **"출석 알리미"** 라벨이 붙어 무슨 메시지인지 바로 알아볼 수 있습니다. (게시글 헤더에는 내 계정 이름이 그대로 뜹니다 — Mattermost 서버 설정상 확장에서 바꿀 수 없는 부분입니다)
- 쉬는 날(주말·공휴일·등록한 휴무일)이 아닐 때만 동작하며, 크롬이 실행 중이어야 합니다.

> **이 설정은 필수입니다.**
> 마치기 전에는 **화면 강조도 켜지지 않습니다.** 화면 강조와 크롬 알림은 SSAFY 페이지를 열어놓고 있을 때만 보이는데, 자리를 비우거나 탭을 닫으면 소용이 없고 정작 놓치는 순간이 바로 그때입니다. 폰으로 푸시가 오는 이 경로까지 갖춰야 확장이 제 역할을 합니다.

#### 설정 방법
**설치하면 시작하기 화면이 자동으로 열리고, 첫 화면이 이 설정입니다.** 버튼 두 번이면 끝납니다.

> ⚠️ **Mattermost 데스크탑 앱 로그인은 인식되지 않습니다.** 연결은 브라우저에 남은 로그인 세션(쿠키)을 그대로 쓰는데, 설치형 앱은 로그인 정보를 자기 저장소에 들고 있어서 크롬에서는 보이지 않습니다. **반드시 크롬에서 `meeting.ssafy.com` 웹페이지로 로그인**한 뒤 연결하세요. (앱에만 로그인한 상태로 누르면 "로그인되어 있지 않아요"가 뜹니다)

1. **🌐 크롬에서 Mattermost 웹 열기** — 새 탭에서 웹페이지로 로그인되어 있는지 확인합니다
2. **🔗 내 계정 연결하기** — `meeting.ssafy.com` 접근 권한을 허용하면, 내 계정으로 **내 전용 알림 통로**를 만들고 아이디도 서버에서 읽어옵니다
3. **테스트 메시지 보내기**로 도착하는지 확인

나중에 다시 설정하려면 팝업 → **💬 Mattermost 알림** 에서 같은 버튼을 쓸 수 있습니다.

연결하면 Mattermost에 **`SSAFY 출석 알림` 비공개 채널**이 하나 생깁니다. 웹훅을 걸어둘 자리이고, 실제 알림은 거기가 아니라 **개인 메시지(DM)로** 옵니다. (웹훅은 DM 채널에 직접 걸 수 없어서 이름 있는 채널이 하나 필요한데, 전체 공개 채널에 걸면 나중에 아이디가 빠졌을 때 팀 전원에게 알림이 갑니다. 나만 있는 비공개 채널이면 그런 실수가 나도 나만 봅니다)

#### 왜 각자 자기 통로를 쓰나
Mattermost는 보통 **자기가 쓴 글에는 알림을 주지 않지만, 웹훅이 쓴 글만은 예외로 글쓴이에게도 알림을 보냅니다.** 게다가 웹훅이 만드는 DM 방에는 언제나 웹훅 주인이 참여자로 들어갑니다. 그래서 통로 하나를 여럿이 나눠 쓰면 그 주인 한 사람이 **모든 사람의 출석 알림을 자기 폰으로 다 받게** 됩니다. 쓰는 사람이 늘수록 감당이 안 됩니다.

내 계정으로 만든 통로는 글쓴이가 나 자신이라 **내 알림이 나에게만** 갑니다. 예전에 이 방식을 안 쓴 이유는 "통합 메뉴에 직접 들어가서 만들기"가 길고 중간에 포기하기 쉬워서였는데, 이제 확장이 그 단계를 대신 밟아줍니다. **공용 통로는 두지 않습니다** — 남겨두면 연결이 실패했을 때 조용히 그쪽으로 새어 나가고, 그게 정확히 없애려던 문제입니다.

#### 아이디는 직접 넣지 않습니다
아이디는 `/users/me` 에서 읽어옵니다. 손으로 넣을 길이 없으므로 이 세 가지가 아예 일어나지 않습니다.

| 예전에 있던 사고 | 지금 |
|---|---|
| 오타를 내면 조용히 실패 | 서버가 준 값이라 오타가 불가능 |
| 남의 아이디를 넣으면 그 사람에게 감 | 내 계정의 아이디만 들어감 |
| 비워두면 웹훅 채널 전체에 울림 | 비어 있을 수가 없음 (비면 한 건도 안 나감) |

> **폰 푸시가 안 오면 여기부터 확인하세요.**
> Mattermost 기본 알림 설정은 **"멘션과 DM만"** 푸시합니다. DM으로 받고 있는데도 안 온다면, 폰 Mattermost 앱의 알림 설정을 확인하세요.

### 📅 공휴일·연차 인식 (holidays.js)
**쉬는 날에는 강조도 알림도 전부 꺼집니다.** 예전에는 주말만 걸렀기 때문에 광복절이나 설 연휴에도 08:50 알림이 오고, 18:00부터 Mattermost로 `🚨 아직 퇴실 체크를 안 했어요!` 가 반복해서 날아갔습니다.

쉬는 날로 보는 기준은 세 가지입니다.

| 종류 | 판단 방법 |
|---|---|
| 주말 | 토·일 |
| **공휴일** | 확장에 내장된 표 (대체공휴일 포함) |
| **개인 휴무일** | 팝업 **📅 쉬는 날**에서 직접 등록 (연차·공가·병가 등) |

#### 대체공휴일은 표가 아니라 규칙으로 계산합니다
설날·추석·부처님오신날만 음력이라 양력 날짜를 표에 적어두고, 대체공휴일은 「관공서의 공휴일에 관한 규정」을 코드로 옮겨 계산합니다. 사람이 옮겨 적다 틀릴 여지를 줄이기 위함입니다.

- 설날·추석 연휴는 **일요일**과 겹칠 때만 대체공휴일이 생깁니다 (토요일과 겹치는 건 해당 없음)
- 그 외 대체 대상 공휴일은 **토·일** 어느 쪽과 겹쳐도 생깁니다
- 신정과 현충일은 대체 대상이 아닙니다

> 예) 2026년 광복절은 토요일이라 8/17(월)이 대체공휴일이지만, 추석 연휴 마지막 날 9/26은 토요일이라 **대체공휴일이 없습니다.** 9/28(월)은 평범한 평일입니다.
>
> 제헌절(7/17)은 2026년부터 다시 공휴일입니다.

#### 팝업 📅 쉬는 날
- 오늘이 왜 쉬는 날인지(공휴일 이름·주말·등록한 휴무일) 그대로 보여줍니다
- 날짜를 골라 **연차 등록** → 그날은 강조·알림이 모두 꺼집니다. 지난 날짜는 목록에서 자동으로 빠집니다
- 공휴일인데 **출석해야 한다면 `그래도 오늘 출석함`** 을 누르면 그날만 평일로 취급합니다 (내장된 표가 틀렸을 때의 탈출구)
- 내장 표에 없는 연도가 되면 그 사실을 팝업에 표시합니다. 이때는 예전처럼 평일이면 항상 동작하므로, **조용히 놓치는 일은 없습니다**

> 개발자 모드의 **주말·공휴일에도 평일처럼 동작**을 켜면 이 판정을 통째로 무시하고 테스트할 수 있습니다.

### ⏱️ 입실·퇴실 전 홈 자동 열기 (background.js)
설정한 분(기본 5분) 전에 **SSAFY 출석 홈페이지를 자동으로 새 탭으로 엽니다.**

- 입실: 09:00 기준 N분 전 (예: N=5 → 08:55)
- 퇴실: 18:00 기준 N분 전 (예: N=5 → 17:55)
- 팝업의 **⏱️ 입실·퇴실 전 홈 자동 열기**에서 켜기/끄기 및 분(0~120) 설정
- 쉬는 날(주말·공휴일·등록한 휴무일)이 아닐 때만 동작하며, 크롬이 실행 중이어야 합니다. 설정은 `chrome.storage.local`에 저장되어 즉시 알람이 다시 예약됩니다.

### 🔄 업데이트 공지 전달 (background.js)
관리자가 **GitHub Release를 발행**하면, 그때 작성한 **릴리즈 노트(제목·내용)가 사용자에게 크롬 알림으로 그대로 전달**됩니다. 버전 숫자를 비교하는 게 아니라, "새 Release가 올라왔는지"로 판단합니다.

- 확인 대상: `https://api.github.com/repos/park-rudxo/ssafy-check/releases/latest`
- 확인 주기: **평일 08:45~18:00 사이 15분 간격**으로 조용히 확인만 하고, **새 Release가 있을 때만** 알림 1회를 띄웁니다. (수업 시간대에만 확장을 볼 것이라는 전제)
- 팝업의 **`업데이트 확인`** 버튼은 시간대와 무관하게 언제든 눌러 미리볼 수 있습니다 (단, 크롬 알림은 뜨지 않고 팝업에만 표시)
- 알림 클릭 시 릴리스 페이지(전체 노트 + 다운로드)로 이동
- **웹스토어 빌드에서는 이 확인 자체가 돌지 않습니다.** 크롬이 알아서 갱신하므로 공지가 필요 없고, GitHub 호스트 권한도 웹스토어 빌드에서는 빠집니다. 아래 내용은 압축 해제로 설치한 개발용 빌드에만 해당합니다.
- 설치 직후에는 "현재 최신 Release"를 이미 본 것으로 기준을 잡아, 방금 설치한 사용자에게 곧바로 알림이 뜨지 않습니다.

#### 🚀 배포하는 법 (관리자)

**사용자에게 실제로 나가는 것은 크롬 웹스토어에 올린 빌드뿐입니다.** GitHub Release 는 변경 이력을 남기는 용도이고, 그것만으로는 사용자에게 아무것도 전달되지 않습니다.

1. `manifest.json` 의 `"version"` 을 올리고 커밋/머지
2. GitHub → **Releases → Draft a new release** → 태그 지정 후 **Publish release**
   - 발행하면 `release-zip.yml` 이 돌아 **웹스토어 제출용 zip** 이 Actions 아티팩트로 올라갑니다
3. Actions 에서 `webstore-vX.X.X` 아티팩트를 받아 **[크롬 웹스토어 개발자 대시보드](https://chrome.google.com/webstore/devconsole)** 에 업로드하고 심사를 제출합니다
4. 심사가 통과되면 크롬이 사용자 확장을 알아서 갱신합니다

> Release 에 함께 붙는 **설치용 zip 은 지금 쓰이지 않습니다.** 웹스토어 이전에 압축 해제로 설치하던 때의 잔재입니다.

### 🎓 첫 설치 랜딩 + 초기 설정 (welcome.html)
설치를 마치면 **랜딩 페이지가 자동으로 열립니다.** 무엇을 해주는 확장인지 먼저 보여준 뒤(입실·퇴실 규칙, 세 가지 알림 방식, 화면 강조 미리보기) **설정 시작하기**로 마법사에 들어갑니다. 마법사의 첫 단계는 **Mattermost 연결**이고, 이 단계는 건너뛸 수 없습니다.

| 화면 | 내용 |
|---|---|
| 0. 랜딩 | 입실·퇴실 규칙, 화면 강조/크롬 알림/Mattermost 푸시 소개, 실제 화면 미리보기(빨간/주황 박스) |
| 1. **Mattermost 연결 (필수·건너뛸 수 없음)** | ① 크롬에서 웹 로그인 확인 → ② 내 계정 연결 → ③ 테스트 전송 (데스크탑 앱 로그인은 인식되지 않는다는 경고를 화면 위에 붙여둡니다) |
| 2. 알림 방식 | 크롬 알림 안내 + 홈 자동 열기 설정 |
| 3. 완료 | 설정 요약 + 주의사항 + SSAFY 페이지 열기 |

- 1단계에서 **테스트 메시지가 실제로 도착하는지 확인**한 뒤 넘어갈 수 있어, 설정이 잘못된 채로 끝나지 않습니다.
- 권한을 허용하지 않으면 다음 단계로 넘어가지 않고 그 자리에서 다시 시도할 수 있습니다.
- 팝업의 **🎓 사용법 다시 보기 · 초기 설정** 으로 언제든 다시 엽니다.
- 여기서 설정한 값은 팝업과 같은 저장소를 쓰므로 그대로 이어집니다.

### 🛠️ 개발자 모드 (팝업 하단)
실제 시간·출석 상태와 무관하게 강조 효과를 테스트할 수 있습니다. 툴바 아이콘 → **개발자 모드** 섹션을 펼쳐서 사용합니다.

- **개발자 모드 켜기**: 아래 오버라이드 설정을 활성화합니다.
- **가상 시각**: 지정한 시각인 것처럼 강조 로직을 동작시킵니다 (예: 08:30, 18:30).
- **입실 상태**: 자동 감지 / 입실 전 / 입실 완료 중 선택.
- **주말에도 평일처럼 동작**: 주말에 테스트할 때 사용.
- **원클릭 미리보기**:
  - `🟥 입실 강조` — 08:30·입실 전 시나리오로 입실 버튼 강조를 즉시 확인
  - `🟥 퇴실 강조` — 18:30·입실 완료 시나리오로 퇴실 버튼 강조를 즉시 확인
  - `⏹ 미리보기 끄기` — 실제 시간·상태 기준으로 복귀

> 강조는 **열려 있는 `edu.ssafy.com` 탭**에 나타납니다. 설정은 `chrome.storage.local`에 저장되어 팝업과 페이지가 실시간으로 연동됩니다. 실제 사용 시에는 개발자 모드를 꺼두세요.

## 동작 원리

- 페이지의 텍스트("입실", "퇴실하기", "정상 출석")를 기반으로 버튼과 출석 상태를 찾기 때문에 SSAFY 페이지의 세부 구조가 조금 바뀌어도 동작합니다.
- 출석 상태는 위젯(`.wrap-going`)의 `.state` / `.state2` 안에 있는 시각(`.t1`)을 읽어 판단합니다. 이 구조를 못 찾으면 **"미체크"로 간주해 경고를 보내는 쪽**으로 실패합니다. 조용히 놓치는 것보다 한 번 더 알리는 쪽이 안전하기 때문입니다.
- 15초마다 + DOM 변경 시마다 상태를 다시 확인합니다.
- **시각은 PC 로컬 시계가 아니라 사이트(서버) 시각 기준으로 판단합니다.** `edu.ssafy.com`에 가벼운 요청을 보내 응답의 `Date` 헤더로 서버 시각과 로컬 시각의 오차를 구해, 카운트다운·마감 판정·클릭 기록에 모두 이 보정된 시각을 씁니다. PC 시계가 서버보다 빨라서 화면은 "지금 퇴실하세요"로 바뀌었는데 실제로는 아직 18:00 전이라 서버에 조퇴로 찍히는 문제를 막기 위함입니다. 계속 주기적으로 보내지 않고, 페이지 로드 시 1회 + **입실(09:00)·퇴실(18:00) 마감 5분 전(08:55, 17:55)에만** 재보정합니다.

## 주의사항

- 이 익스텐션은 **자동으로 버튼을 눌러주지 않습니다.** 출석 체크는 본인이 직접 해야 하며, 익스텐션은 놓치지 않도록 시각적으로 알려주는 보조 도구입니다.
- 공휴일 정보는 확장에 내장되어 있어 **표에 있는 연도까지만** 정확합니다. 표에 없는 연도가 되면 팝업이 알려주고, 그때는 예전처럼 평일이면 항상 동작합니다 (쉬는 날을 직접 등록해 쓸 수 있습니다).
- Mattermost 미체크 경고는 **백그라운드에 마지막으로 보고된 상태**를 기준으로 합니다. SSAFY 탭을 하루 종일 한 번도 열지 않았다면 위젯을 읽을 기회가 없어, 폰으로만 퇴실한 경우 경고가 갈 수 있습니다. 홈 자동 열기(기본 5분 전)를 켜두면 이 문제가 대부분 해소됩니다.
